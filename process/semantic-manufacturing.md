# Semantic Manufacturing

## Purpose

Turn admitted semantics into reproducible artifacts while minimizing repeated intelligence.

```text
O*
-> prior-art/capability closure
-> reuse
-> compose
-> extend
-> invent irreducible residue
-> manufacture
-> qualify
-> promote novelty into reusable capital
```

## Capital order

Before handwriting a repeatable surface:

1. existing public standard/ontology;
2. framework-native generator/compiler/migration engine;
3. admitted ggen-marketplace pack;
4. composition of known tools/templates;
5. extension of existing generator/profile;
6. novel handwritten mechanism.

Novelty requires a concrete falsifier explaining why the existing capability cannot satisfy required semantics.

## Source and projections

Canonical semantic/source material is durable capital.

Generated code, docs, schemas, clients, manifests, tickets, plans, and configuration are projections/inventory when reproducible from source + generator identity.

Do not hand-edit generated projections.

## Framework-native generator law

A framework-native generator is capital equipment, not competition with semantic manufacture.

Upstream manufacture should generate:
- declarations;
- schemas;
- configuration;
- generator invocations;
- framework-native inputs.

Then the specialized generator creates framework output.

Example shape:

```text
ontology
-> project/framework declarations
-> native generator
-> generated source
-> verifier
```

## Generator capability gap

When generation is impossible, record:

```text
UNSUPPORTED(generator-capability)
generator=<exact identity>
required_semantic=<what cannot be expressed>
falsifier=<observation proving gap>
handwritten_residue=<smallest fallback>
promotion_path=<what generator extension would retire it>
```

Do not turn a temporary tool failure into a permanent claim of irreducibility.

## Determinism

Where deterministic manufacture is claimed:
- bind graph/source digest;
- bind generator/toolchain/config version;
- manufacture twice from clean state;
- compare declared consequence set/bytes as appropriate;
- emit receipt.

## Novelty promotion

After a handwritten mechanism repeats successfully:

```text
observe recurrence
-> extract parameters/invariants
-> ontology/type/schema/template
-> generator/verifier
-> qualification
-> replace repeated handwritten transform
```

Intelligence succeeds when the next instance requires less intelligence.
